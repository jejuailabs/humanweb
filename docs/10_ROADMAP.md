# 10. 개발 순서

단계는 **기능 묶음을 구분하는 페이즈**다. 개발은 전체를 함께 착수하며, 각 페이즈는 자기 **완료 기준**을 만족해야 완료로 본다.
의존 관계(예: 스탯 → 매칭 점수)가 있는 작업은 앞 페이즈의 데이터 구조를 먼저 확정한다.

## 0단계 — 기반
- Next.js + Firebase(dev/prod) + Vercel 연결, next-intl(ko/en), 테마 토큰·토글, 하단 탭 골격
- **완료 기준**: `/ko`, `/en` 전환과 라이트/다크/시스템 전환이 모든 화면 골격에서 동작한다.

## 1단계 — 가입과 공용 데일리 운세
- 로그인, 최소 온보딩(닉네임·생년월일·혈액형)
- `generateDaily` (별자리·혈액형·띠·MBTI, ko/en), 검사, 예비 문장 풀
- 데일리 대시보드 (공용 탭), 날짜 이동
- 어드민: 콘텐츠 상태 + 재생성
- **완료 기준**: 가입 직후 별자리·띠·혈액형 운세가 보이고, 다음 날 자동으로 바뀐다. 생성 실패 시 예비 문장이 보이고 어드민에 경고가 뜬다.

## 2단계 — 한 줄 일기장
- 일기 작성·수정·삭제, 기분 태그, 공개/비공개 (기본 비공개)
- `onDiaryWrite` 공개 사본 동기화, 보안 규칙 + 에뮬레이터 테스트
- 데일리 대시보드의 "오늘의 한 줄" 카드, 달력/목록 보기
- 스트릭 (데일리 확인 또는 일기 작성)
- **완료 기준**: 비공개 일기는 다른 계정에서 어떤 방법으로도 읽히지 않는다(규칙 테스트 통과). 공개→비공개 전환 시 공개 사본이 즉시 사라진다.

## 3단계 — 사주와 개인 운세
- 만세력 라이브러리 선정·검증, 사주 계산, 사주 풀이
- 일간별 운세 생성, 개인 오늘의 운세
- **완료 기준**: 정답표 테스트(절기 경계·윤달·자시 포함) 통과. 태어난 시간 모름도 개인 운세가 나온다.

## 4단계 — MBTI, 스탯, AI 종합 보고서
- MBTI 검사/입력, 별자리·혈액형 스탯 매핑
- 스탯 계산(05 문서 식), 신뢰도, 레이더 차트, 종합 대시보드
- AI 종합 보고서 + 버전 기록
- **완료 기준**: 05 문서의 예시 입력에 대해 스탯이 식과 일치한다. 분석을 추가하면 스탯·보고서가 자동 갱신된다.

## 5단계 — AI 대화
- 프로필 컨텍스트, 기억 저장·열람·삭제, 일기 AI 허용 토글, 일일 한도
- **완료 기준**: 생년월일 원본·실명이 프롬프트에 포함되지 않음을 로그로 확인. 기억 삭제가 다음 대화에 반영된다.

## 6단계 — 확장
- 토정비결, 손금 분석, 공개 일기 둘러보기·하트·신고, 공유 카드, 데일리 스탯 보정
- 어드민 퍼널·신고 처리·사용자 관리

## 7단계 — 네트워크·매칭 → `09_MATCHING.md`
- 스탯 벡터 검색, 연결 점수 계산, 지도 탭(인연선), 매칭 상세, 연결 요청·수락
- 차단·신고·인증 (`00_OVERVIEW.md` 안전 장치)
- **착수 전 결정**: `09_MATCHING.md`의 "별도 결정 필요" 항목, 그래프 라이브러리
- **완료 기준**: 비공개 항목이 점수·지도·매칭 상세 어디에도 노출되지 않는다(규칙 테스트 통과). 빨간 선이 한 사람당 3개를 넘지 않는다.
